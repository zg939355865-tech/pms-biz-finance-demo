# PMS PRD/UR 文档生成规范

## 1. 生成机制

1. PMS项目后续生成PRD、UR或需求规格说明书时，默认使用 `$mes-ur-generator`。
2. 文档结构、格式、截图、流程图和生成方式以 `$mes-ur-generator` 自带规范为准，项目规则不得注入其他模板 Skill 的结构或视觉样式。
3. 用户明确指定其他文档生成 Skill 时，以用户指定的 Skill 为准。
4. 项目保留的历史Word模板仅作参考资料，不作为默认生成入口。

## 2. 输入来源

按以下优先级组织PRD内容：

1. 用户本轮明确确认的需求、修改意见和业务规则。
2. `inputs/md/requirements/` 中的原始需求。
3. `inputs/md/pages/` 中已确认的页面蓝图。
4. `schemas/pages/` 中的正式字段、组件、状态、交互和数据约束。
5. `pages/` 与 `menu/index.html` 中已验收的页面和菜单关系。
6. `rules/` 中的项目公共规则。

存在冲突时，按“用户最新确认 > 项目级规则 > 页面蓝图 > 正式Schema > 当前原型”的顺序处理，并在“问题澄清”章节记录未解决事项。

## 3. 文档结构

PRD/UR原则上沿用基准文档的章节体系：

1. 引言：目的和范围、目标读者。
2. 文档说明：文件信息、版本记录、审批信息、引用资料。
3. 术语、定义和缩略语。
4. 目标用户：角色、职责、使用边界。
5. 需求场景：业务背景、目标、痛点和业务价值。
6. 架构设计：系统边界、模块关系、上下游数据关系。
7. 详细设计：公共规则、状态、权限、数据和异常处理。
8. 功能设计：按菜单或功能模块逐项描述。
9. 流程设计：主流程、分支流程、异常流程和状态流转。
10. 问题澄清：待确认事项、影响范围、责任人和处理状态。

不适用的章节必须写明“不适用”及原因，不得无说明删除章节。

## 4. 功能书写规范

每个功能至少说明：

1. 功能目标和适用场景。
2. 使用角色及权限。
3. 前置条件和数据来源。
4. 页面入口和关联页面。
5. 查询条件、列表字段、详情字段和表单字段。
6. 按钮、操作、状态和交互反馈。
7. 业务规则、校验规则和计算边界。
8. 正常流程、异常流程及边界情况。
9. 数据新增、修改、删除、留痕和审计要求。
10. 验收标准。

只写已经确认或有来源依据的内容。未知信息统一标记为“待确认”，不得为填满模板而编造业务事实。

## 5. 格式与视觉规范

1. 页面尺寸、页边距、封面、标题、正文、表格、目录、页眉和页脚样式以 `$mes-ur-generator` 当前规范为准。
2. 页面截图必须来自当前 `menu/index.html` 或 `pages/`，不得使用过期截图。
3. 截图应完整、清晰并配图题；同一页面只保留能说明需求的必要画面。
4. 流程图必须与正文中的角色、状态和操作一致。
5. 跨页表格必须重复表头，不得出现内容截断、错位或异常留白。
6. 目录必须刷新至最终页码并支持点击跳转；是否显示页脚和页码由 `$mes-ur-generator` 规范及用户本轮要求决定。

## 6. 生成流程

```text
需求及已确认原型
  -> 汇总需求来源与冲突项
  -> 按 `$mes-ur-generator` 组织章节和内容槽位
  -> 生成PRD/UR草稿
  -> 检查字段、按钮、状态、权限和页面关系
  -> 生成DOCX
  -> 全页渲染并逐页检查
  -> 修复版式与内容问题
  -> 输出正式版本到独立交付目录
```

## 7. 验收要求

交付前必须检查：

- 章节体系、编号和目录完整。
- 需求与已确认蓝图、Schema、原型一致。
- 字段、按钮、状态、权限、流程和异常规则无遗漏。
- 文档不存在重复内容、虚构内容或过期截图。
- 封面、页眉、表格、图片和分页无错位；所有页脚保持空白。
- DOCX完成全页渲染并逐页检查；发现截断、重叠、乱码或异常留白必须修复后重验。
- 最终文件命名为：`PMS业财一体化系统_{模块名称}_需求规格说明书_{YYYYMMDD}_V{主版本}.{次版本}.docx`。

## 8. 交付与版本管理

1. 每次生成任务在 `prd-assets/` 下建立唯一正式交付目录：`prd-assets/deliveries/{模块名称}/{YYYYMMDD}-V{版本}/`。
2. 同次任务的正式DOCX、来源清单和必要的待确认事项统一放入该目录，不得散放在 `prd-assets/` 根目录、`docs/PRD/` 或其他位置。
3. 临时文档、渲染图、PDF和检查结果统一存放在 `outputs/prd/{模块名称}/{YYYYMMDD}-V{版本}/`，不得混入正式交付目录。
4. 每次正式修改必须更新封面版本、文档修订记录和文件名版本。
5. 不得覆盖已发布版本；修订后生成新版本文件。
