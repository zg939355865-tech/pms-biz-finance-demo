# 项目驾驶舱页面蓝图

## 本次设计（2026-09-10）

- 状态：按用户明确提出的七类内容实施。
- 页面编码：`project-lifecycle-dashboard`；菜单：项目驾驶舱。
- 输出：`pages/report/project-lifecycle-dashboard.html`。
- 主体采用深蓝大屏主题，青蓝强调、白色关键数值、弱分隔线；使用共享资源中心中的屏幕色与图表色 Token，不改变菜单及其他业务页面。
- 资源中心：`prototype-resources/index.html`，`pms-resource-center-v1`。
- 参考样例：数据看板页、标准列表页；组件映射：PageHeader、ProStatCard、ProChartCard、Space、ProSearchForm、ProTable、Tag。差异：用户明确要求驾驶舱视觉，主体采用页面专用深色布局；原有标准查询与明细保留在底部折叠区。

## 1. 主体结构

1. 页头：项目驾驶舱、演示数据标识、统计截至月份、所属行业、重置。
2. 指标卡：项目需求（总数/审核中/已完成/已终止）、项目方案（总数/审核中/已完成/已终止）、项目实施通知（总数/审核中/已完成）、项目立项（总数/审核中/未开始/进行中/已完成）。
3. 第一排：项目需求月度面积折线图、五行业月度折线图、行业需求环形构成图。
4. 第二排：需求类型柱状图、省份需求排名前7、需求提出人排名前7、项目经理负责项目数倒序排名（全部经理）。
5. 底部：统计口径入口、可展开的生命周期明细与查询。

## 2. 枚举及数据粒度

- 行业：污水厂、水泥、钢铁、化工、光伏。
- 需求类型：曝气智能体、进水提升泵智能体、加活性炭智能体、内回流智能体、排泥智能体。横轴可简写，图形可访问名称和明细保留完整语义。
- 省份：项目所在地省份；人员：需求发起人、项目主责经理。
- 主体数据来源：正式 Schema 的 `cockpit.records`。四类记录分别按唯一单据编号去重，需求图表只统计需求记录，经理排名只统计立项记录。
- 演示总数：需求186、方案84、通知62、立项48。所有主体图表实时从同一记录集聚合，不直接写死图表总量。

## 3. 统计口径

1. 本页面使用独立演示数据，不代表真实业务业绩。所有主体指标与图表均从同一组演示记录聚合；月份随访问当月平移。
2. 统计范围：所选截至月份及前5个月。趋势按各月新增需求计算，缺失月份补零；截至月份内的数据为该月已收录数据，未必是完整自然月。环比上月为0时显示“—”。
3. 项目需求、项目方案、项目实施通知：“已完成”在本驾驶舱表示审批已完成。项目立项先判断审核中；审核完成后按项目执行状态计入未开始、进行中、已完成，四类互斥。
4. 总数按唯一单据编号统计；正式接入时总数应包含草稿、退回等其他状态，指标卡列出的状态子项不一定覆盖总数。当前样例只覆盖卡片列出的状态。
5. 行业按需求所属行业、省份按项目所在地、提出人按需求发起人统计；本样例每条需求只归属一个行业、一个省份和一个需求类型。正式数据未分类项应另列，不能静默丢弃。
6. 省份和需求提出人取需求数前7名；同数按名称排序。项目经理排名按负责项目数倒序展示全部经理，包括审核中的立项，每个项目只归属一位主责经理。
7. 行业趋势图例可切换系列显示，不改变统计范围；页头行业筛选作用于全部主体指标和图表。点击指标或图表查看对应演示明细，固定5条/页。
8. 底部生命周期明细保留原有独立12条样例及查询、图表联动、业务页面下钻，不与主体演示统计混算。

## 4. 交互与边界

- 修改截至月份或行业：同步重新计算四组指标及七张图表；重置恢复访问当月及全部行业。
- 趋势始终显示连续6个月；图例控制行业系列显隐，不改变指标总量。
- 指标总数/状态、趋势数据点、行业图例、类型柱、省份/提出人/经理排名均可点击查看对应演示记录。
- 明细弹窗支持关闭、Escape、上一页/下一页，固定5条/页；空数据保留表头并显示提示。
- 零记录时总数为0，趋势补零，环形图显示空环，排名显示空提示；避免除零、NaN、Infinity。
- 主体演示记录不伪造已存在的业务详情链接；底部旧样例继续使用原有真实页面入口。
- 页面无审批、编辑、删除或财务记账操作。

## 5. 生成和验收

- 标准命令：`node scripts/generate/page-from-schema.mjs schemas/pages/report/project-lifecycle-dashboard.json`。
- 页面专用渲染：`scripts/lib/project-cockpit.mjs`、`project-cockpit.css`、`project-cockpit-runtime.mjs`；仅在目标页面且配置了 `cockpit` 时启用。
- 检查目标页面 Schema、Policy、HTML、专项交互以及1440px/2048px直接页面和菜单 iframe；保留旧明细断言。
- 不修改其他页面、菜单、公共样式或原有单据状态定义。

## 2. 需求理解与 AI 假设

### 2.1 用户明确要求

1. 采用“综合驾驶舱”，支持企业总览、项目群监控和单项目下钻。
2. 项目全生命周期包含需求、调研、方案、实施通知、立项、计划、执行、验收和运营维护。
3. 运营维护覆盖所有项目，不仅限于包含智能体的项目。
4. 不包含财务指标。
5. 不设置项目健康度、综合评分或模糊分级，只展示可追溯、可直接计算的业务指标。

### 2.2 AI 补充内容与假设

1. 默认统计日期范围为本年度，支持按日期、项目/需求、生命周期阶段、项目状态、项目负责人、项目类型、项目主责公司和区域筛选。
2. 生命周期前四阶段按“待立项事项”统计，已立项后按项目编码统计，避免把未立项需求误称为已立项项目。
3. 验收阶段以项目阶段、验收资料和验收报告的可用记录为原型口径；后续实系统需补齐通用验收状态。
4. 运营维护指标来自通用项目运维记录；智能体运营数据仅作为包含智能体项目的专项下钻。

## 3. 业务目标与范围

### 3.1 业务目标

在一个看板中展示项目从需求到运营维护的当前分布、执行进度和明确异常，并支持从指标下钻到项目或上游业务单据。

### 3.2 主要使用人员

- 公司管理层：查看整体规模、阶段分布和明确延期数量。
- PMO/项目管理部门：查看计划、进度、任务、里程碑、交付物和运维问题。
- 项目经理：从明细下钻到本人负责项目及其 WBS、进度和问题记录。

### 3.3 本次包含

- 八项顶部直接指标。
- 九阶段生命周期分布和项目状态分布。
- 项目/前期事项明细表、筛选、分页和下钻。
- 延期、超过7天未填报、缺失必交文档和超期未解决问题等客观数量。

### 3.4 本次不包含

- 合同、收入、支出、成本、预算、发票、收付款和凭证等财务指标。
- 健康度、风险评分、主观权重、预测性结论。
- 在看板内新增或修改业务单据。

### 3.5 业务链路

```text
项目需求 -> 调研问卷 -> 项目方案 -> 项目实施通知 -> 项目立项
-> 项目计划 -> 项目进度/WBS -> 验收 -> 项目运营维护
```

## 9. 业务规则与校验

| 编号 | 触发时机 | 条件 | 处理结果 | 提示文案 |
| --- | --- | --- | --- | --- |
| R01 | 指标聚合 | 存在已审核项目立项记录 | 按唯一项目编码计入“已立项项目” | 不适用 |
| R02 | 阶段判定 | 同一业务链路存在多个阶段记录 | 只按已完成的最后阶段显示一次 | 不适用 |
| R03 | 延期计算 | 当前日期大于计划完成日期，且实际完成日期为空 | 延期天数=当前日期-计划完成日期 | 不适用 |
| R04 | 未填报计算 | 项目已进入执行且当前日期-最近有效进度填报日期>7天 | 计入“超过7天未填报项目” | 不适用 |
| R05 | 文档缺失计算 | 项目阶段配置的必交文档未上传 | 按缺失文档数量展示 | 不适用 |
| R06 | 运维问题计算 | 问题实际解决日期为空 | 计入未解决问题；超过解决截止日期同时计入超期未解决 | 不适用 |
| R07 | 统计去重 | 同一项目存在多条进度或问题记录 | 项目数按项目编码去重，进度取最新已审核记录 | 不适用 |
| R08 | 财务字段检查 | 页面 Schema 或 HTML 出现合同金额、成本、预算、收付款、发票或凭证指标 | 阻断交付 | 项目全生命周期驾驶舱不展示财务指标 |

必填、主明细平衡、状态编辑、删除和金额一致性：不适用，本页为只读看板。

## 10. 关键交互

1. 查询和重置只更新明细范围，不产生 Toast。
2. 图表数据项支持鼠标点击和键盘聚焦；选中态不仅依赖颜色。
3. 明细固定每页5条，显示固定“5条/页”，无页容量下拉和内部纵向滚动。
4. 宽表只在表格内横向滚动，首个编号列固定在左侧。
5. 编号下钻在 iframe 中通过 `postMessage` 打开对应 PMS 标签页，直接访问时跳转到对应页面。
6. 支持加载、空数据和失败态的结构预留；静态原型使用样例数据。
