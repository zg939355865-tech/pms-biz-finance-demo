## 2. 最新需求结论

1. 采购订单不接入流程体系，不显示流程状态、流程动态、当前责任人、流程图、审批面板和终止操作。
2. 使用独立业务状态：草稿、待审核、已审核。草稿在详情提交后变为待审核；列表对待审核订单执行审核，对已审核订单执行反审核，反审核后直接回到草稿。
3. 基础信息与订单行合并到同一“基础信息”页签，详情只保留“基础信息、附件”两个页签。
4. 基础信息字段及顺序调整为：采购订单、状态、订单日期、订单来源、紧急采购原因、需求部门、需求人、期望交货日期、项目、供应商、结算币别、是否存在合同、合同编号、合同名称、付款方式、采购员、创建人、创建时间、审核人、审核时间、所属公司、备注。
5. 紧急采购原因始终展示：普通采购时禁用；紧急采购时必填。
6. 需求部门、需求人和项目使用下拉选择；项目新增时默认为“通用项目”。
7. 供应商后显示只读结算币别，选择供应商后自动带出，新增默认为 CNY。
8. 合同编号前增加“是否存在合同”复选框，仅勾选后允许选择合同；合同弹窗增加编号或名称查询、固定 5 条/页分页，列表仅显示合同编号、合同名称。
9. 合同名称后增加必填付款方式下拉，选项为电汇、承兑；勾选“是否存在合同”后由合同编号自动带出并不可编辑，无合同时手动选择。
10. 付款方式后显示必填采购员下拉，由人员选项中选择。
11. 订单明细统一为可编辑新增模式，普通采购与紧急采购均显示“新增订单行”，不再使用申请来源行和恢复来源行。
12. 不设置独立金额汇总区；订单明细底部使用合计行汇总采购数量、价税合计、税额和不含税金额。
13. 订单明细字段顺序为：序号、采购类别、采购名称、规格、单位、采购数量、含税单价、价税合计、税率、税额、不含税金额、不含税单价、备注、操作。
14. 采购订单列表字段依次为：订单编号、状态、订单日期、供应商、项目、金额合计、税额合计、价税合计、采购员、订单来源、创建人、创建时间、操作。
15. 列表查询条件依次为：订单编号、状态、订单日期、供应商、项目、采购员、订单来源。
16. 查询条件“采购员”使用输入框。
17. 详情基础信息在创建时间后显示只读审核人、审核时间；待审核订单执行审核后写入，反审核回到草稿时清空；列表不显示这两个字段。

## 3. 业务目标与范围

形成采购订单并集中维护订单表头与订单行，明确项目、供应商、期望交货日期、订单行和金额，为后续采购入库、收票和付款提供来源依据。

包含：订单查询、分页、新增、草稿编辑/删除、提交、列表审核/反审核、普通/紧急采购、多明细、税额换算、附件维护和基础数据选择。

不包含：流程审批、审批层级、终止、采购比价、招投标、预算占用、订单变更版本和正式支出合同管理。

| 视图 | 说明 |

## 5. 页面区域

### 5.1 列表视图

- 标题操作：批量删除、审核、反审核、新增。
- 查询区域：订单编号、状态、订单日期、供应商、项目、采购员、订单来源、业务类型。
- 列表字段：订单编号、状态、订单日期、供应商、项目、金额合计、税额合计、价税合计、采购员、订单来源、业务类型、创建人、创建时间、操作。
- 订单编号固定在左侧；金额合计、税额合计、价税合计右对齐；草稿订单编号进入编辑，待审核和已审核进入查看。
- 草稿可删除；待审核和已审核不可删除。所有状态可勾选，具体操作按状态启用。

### 5.2 详情视图

- 页头：返回列表；草稿显示保存草稿、提交。无流程相关入口。
- 页签：基础信息、附件。
- 附件列表仅展示文件名、大小、上传人、上传时间、操作，不展示资料类型。
- 基础信息页签内按顺序展示基础信息表单和订单明细；不显示独立金额汇总卡片，仅保留明细表合计行。

### 6.1 基础信息

| 字段 | 控件 | 必填 | 规则 |
| --- | --- | --- | --- |
| 采购订单 | 只读文本 | 是 | `PO+YYYYMMDD+3位序号` |
| 状态 | 只读下拉 | 是 | 草稿、待审核、已审核 |
| 订单日期 | 日期 | 是 | 新增默认为当天 |
| 订单来源 | 下拉 | 是 | 普通采购、紧急采购 |
| 紧急采购原因 | 输入框 | 紧急采购必填 | 始终展示；普通采购时禁用 |
| 业务类型 | 下拉 | 是 | 实物采购、服务采购；位于需求部门之前 |
| 需求部门 | 下拉 | 否 | 从部门选项中选择 |
| 需求人 | 下拉 | 否 | 从人员选项中选择 |
| 期望交货日期 | 日期 | 是 | 整单日期 |
| 项目 | 下拉 | 是 | 新增默认为通用项目 |
| 供应商 | 选择器 | 是 | 供应商档案 |
| 结算币别 | 只读下拉 | 是 | 选择供应商后自动带出，新增默认为 CNY |
| 是否存在合同 | 复选框 | 否 | 勾选后才可选择合同编号；取消勾选清空合同编号、合同名称 |
| 合同编号 | 选择器 | 否 | 仅勾选“是否存在合同”后启用；弹窗字段仅为合同编号、合同名称 |
| 合同名称 | 只读文本 | 否 | 根据合同编号自动带出 |
| 付款方式 | 下拉 | 是 | 电汇、承兑；存在合同时根据合同编号自动带出并不可编辑，无合同时手动选择 |
| 采购员 | 下拉 | 是 | 从人员选项中选择 |
| 创建人 | 只读文本 | 是 | 公共审计字段 |
| 创建时间 | 只读文本 | 是 | 公共审计字段 |
| 审核人 | 只读文本 | 否 | 审核后写入，反审核后清空 |
| 审核时间 | 只读文本 | 否 | 审核后写入，反审核后清空 |

| 备注 | 输入框 | 否 | 整单备注 |

### 6.2 订单行

区块标题：订单明细。

列顺序：序号、采购类别、采购名称、规格、单位、采购数量、含税单价、价税合计、税率、税额、不含税金额、不含税单价、备注、操作。

- 含税单价、税率变化后同步换算不含税单价、不含税金额、税额、价税合计。
- 普通采购、紧急采购使用相同的可编辑新增样式，均支持新增订单行、批量删除和单行移除。
- 采购类别、采购名称、规格、单位、采购数量、含税单价、税率、备注可编辑；金额字段自动计算并只读。
- 不显示申请数量、来源行号和恢复来源行按钮。
- 订单明细底部显示合计行，汇总采购数量、价税合计、税额和不含税金额，不增加独立汇总区。
- 订单行不包含交付日期。

仅明细字段：`purchaseCategory`、`itemName`、`specification`、`unit`、`orderQuantity`、`taxIncludedUnitPrice`、`taxIncludedAmount`、`taxRate`、`taxAmount`、`taxExcludedAmount`、`taxExcludedUnitPrice`、`itemRemark`。

## 7. 操作定义

| 操作 | 入口 | 状态条件 | 结果 |
| --- | --- | --- | --- |
| 保存草稿 | 详情 | 草稿 | 保存并返回列表，状态不变 |
| 提交 | 详情 | 草稿 | 校验必填和至少一条明细后变为待审核 |
| 审核 | 列表 | 单选待审核 | 状态变为已审核，并写入审核人、审核时间 |
| 反审核 | 列表 | 单选已审核 | 状态直接变为草稿，并清空审核人、审核时间 |
| 删除/批量删除 | 列表 | 仅草稿 | 二次确认后删除 |
| 新增订单行 | 订单行 | 草稿 | 普通采购、紧急采购均新增一条可编辑明细 |
| 移除 | 订单行 | 草稿 | 移除当前行，整单至少保留一行 |

## 8. 状态与权限

```text
草稿 ----提交----> 待审核 --审核--> 已审核
  ^                                  |
  |-------------反审核---------------|
```

- 草稿：可编辑、保存、提交和删除。
- 待审核：只读，可在列表审核。
- 已审核：只读，可在列表反审核。
- 审核时记录审核人、审核时间；反审核时清空两项审核信息。
- 上述为业务状态机，不创建流程实例，不展示流程信息。

## 9. 核心业务规则

1. 采购订单必须绑定归属项目并至少包含一条订单行。
2. 普通采购与紧急采购统一使用可编辑订单明细，不再从采购申请恢复来源行。
3. 结算币别根据供应商自动带出，新增默认 CNY。合同为可选关联，仅勾选“是否存在合同”后允许选择；选择合同后自动带出合同名称和付款方式，付款方式不可编辑；无合同时付款方式可编辑且必填。
4. 期望交货日期为整单字段，独立于明细。
5. 税额及相关金额在明细行内计算，并在表格合计行汇总采购数量、价税合计、税额和不含税金额；基础信息不重复展示汇总字段。
6. 业务类型为整单必填字段，仅允许选择“实物采购”或“服务采购”，并在查询、列表和详情中使用同一字段。

## 10. 关键交互

- 紧急采购原因始终显示；切换订单来源时同步切换必填标识和禁用状态。
- 选择供应商后同步回填结算币别；新增未选择供应商前结算币别默认为 CNY。
- 项目使用下拉选择，新增默认“通用项目”。
- 未勾选“是否存在合同”时合同编号及选择按钮禁用，付款方式可编辑；勾选后付款方式不可编辑；取消勾选时清空合同编号和合同名称并恢复付款方式可编辑。
- 合同选择弹窗支持按合同编号或名称查询，确认后同时回填合同编号、合同名称和只读付款方式。
- 无合同编号时付款方式保持可编辑并必须手动选择。
- 采购员为必填下拉，新增时由用户从人员选项中选择。
- 普通采购与紧急采购均显示“新增订单行”，新增行采用相同的可编辑控件和必填校验。
- 审核/反审核按钮仅在勾选一条符合状态的订单时启用。

## 11. 业财关联

采购订单记录项目、供应商及可选支出合同的关联，为采购入库、采购收票、付款申请提供追溯依据。本期不直接生成财务凭证，也不执行预算占用。

## 12. 组件与公共策略

- 使用 `auditable-list-detail` 非流程审核策略。
- 使用公共 PageHeader、ProSearchForm、ProTable、ProTabsDetail、DetailForm、EditableTable、ProUploadList 和 ProDataSelectModal。
- 不使用 ApprovalPanel、StatusFlow、流程入口、终止弹窗和恢复来源行弹窗。
- 列表固定 5 条/页，不提供页容量选择；字段下方不显示辅助说明文案。

## 13. 示例数据要求

- 列表至少 12 条，覆盖草稿、待审核、已审核和普通/紧急采购。
- 示例订单包含至少 3 条可编辑明细，用于验证新增、批量删除、单行移除和金额联动。

## 14. 验收标准

1. 页面无流程状态、流程动态、当前责任人、流程图、审批面板、终止操作。
2. 状态只有草稿、待审核、已审核，状态转移和按钮权限正确。
3. 详情仅保留基础信息、附件两个页签，基础信息表单与订单行同处基础信息页签。
4. 基础信息字段名称、顺序、控件和默认值符合 2026-09-16 要求。
5. 紧急采购原因始终显示，并按订单来源切换必填与禁用。
6. 结算币别默认 CNY，选择供应商后自动带出；付款方式仅支持电汇、承兑并保持必填。
7. 合同编号受“是否存在合同”复选框控制；合同弹窗具备查询和固定 5 条/页分页，选择后自动带出合同名称及付款方式；存在合同时付款方式不可编辑，无合同时可编辑。
8. 付款方式后显示必填采购员下拉，新增时由用户选择。
9. 订单明细上方显示“订单明细”标题，普通采购和紧急采购均可新增、编辑、批量删除及单行移除。
10. 明细不显示申请数量、来源行号和恢复来源行按钮；底部合计行汇总采购数量、价税合计、税额和不含税金额。
11. 列表及查询字段名称、顺序符合最新要求，金额字段右对齐；列表、查询和详情统一使用采购员，查询采购员为输入框。
12. 详情基础信息在创建时间后显示审核人、审核时间；列表不显示；审核后即时写入，反审核后即时清空。
13. Schema、策略、静态页面及专项交互检查全部通过。
