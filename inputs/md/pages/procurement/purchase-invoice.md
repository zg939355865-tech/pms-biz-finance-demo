# 采购收票页面蓝图

## 1. 蓝图信息

| 项目 | 内容 |
| --- | --- |
| 蓝图状态 | 已确认 |
| 页面名称 | 采购收票 |
| 页面编码 | `purchase-invoice` |
| 页面类型 | 列表详情一体、业务审核单据 |
| 菜单路径 | 采购管理 / 采购收票 |

## 2. 当前设计结论

1. 采购收票采用“上游来源行 + 收票结算行”两级结构：上游来源行只用于限定可选下游和汇总展示，收票结算行是唯一金额事实。
2. 本次收到蓝票时，先选择采购订单行，再从该订单行的下游采购入库行或服务结算行中选择收票结算来源；上游按`采购订单 + 订单行`汇总。
3. 本次收到红票时，先通过“选择蓝字入库/服务结算”选择原蓝字采购入库行或原蓝字服务结算行，再选择对应的采购入库/服务结算来源；上游按`原蓝字采购入库单 + 入库行`或`原蓝字服务结算单 + 结算行`汇总。
4. 实物采购行仅带出采购入库单与入库行，服务采购行仅带出服务结算单与结算行，两类行都必须保留采购订单和订单行。
5. 订单行的税率选择采购订单后直接带出；验票数量、价税合计、税额、不含税金额分别汇总对应收票结算行，含税单价、不含税单价取对应结算行。同一汇总行存在多条结算行时，单价和税率必须完全一致。
6. 上游行刚选择时税率立即显示，数量、金额及含税/不含税单价为空；选择或调整收票结算行后立即派生其余字段。两张表均在表尾合计验票数量、价税合计、税额和不含税金额。

## 3. 页面组成

### 3.1 列表

- 页头操作：批量删除、新增、审核、反审核。
- 查询条件：发票号码、状态、类型、供应商、项目、是否存在合同、合同名称、收票日期。
- 列表字段：发票号码、状态、类型、收票日期、发票金额、验票总金额、供应商、项目、是否存在合同、合同名称、创建人、创建时间。
- 固定每页 5 条，不提供每页条数切换。

### 3.2 详情

详情只保留“基础信息”页签，页签内按以下顺序展示：

1. 基础信息表单。
2. 订单行。
3. 收票结算行。

“订单行”和“收票结算行”均位于基础信息表单下方，不新增独立页签。两张明细表的批量删除按钮文案统一为“删除选中明细”。

## 4. 基础信息

沿用当前已确认的基础信息字段和审核字段，并补充以下录入规则：

1. 新增和草稿状态显示“保存草稿、提交”；保存草稿允许基础信息暂未完整，状态保持“草稿”并返回列表。
2. 收票日期必填，新建时默认当前日期；编辑已有单据时保留原日期。
3. 供应商、项目按订单关系级联且均必填：上游来源弹窗始终以供应商+项目过滤；“是否存在合同”勾选后合同名称启用且必填，并在供应商+项目基础上叠加合同过滤；未勾选时不加入合同条件。
4. 是否盘存使用复选框并默认不勾选；盘存金额只读按“发票金额-验票总金额”自动计算，勾选后盘存原因启用且必填。
5. 保存草稿不执行提交必填校验；提交执行本蓝图第 8 节全部校验。
6. 类型为“红字”时，发票金额输入值自动按负数处理；输入正数自动转换为对应负数，输入负数保持不变。类型切换回“蓝字”时，金额恢复为对应正数。
7. 新增时类型仍为提交必填项；未选择类型时自动来源汇总保持空态，选择类型后按第 5 节规则从来源收票行派生。
8. 所属公司位于审核时间之后、发票附件之前，只读显示具体业务主体“昕彤赋能（长沙）人工智能行业应用系统有限公司”，不得显示“当前登录公司”等占位值。
9. 来源选择按钮始终可点击；“选择采购入库/服务结算”弹窗必须先存在已选上游行，否则显示暂无数据。存在上游行时，在供应商、项目、合同范围内只展示该上游行可追溯的下游采购入库行或服务结算行。
10. 备注前增加“发票附件”上传字段，附件选填；草稿状态允许选择或更换文件，待审核、已审核状态只读。

验票总金额为只读金额字段，保留两位小数：

```text
验票总金额 = 订单行价税合计汇总
```

## 5. 订单行

订单行先通过采购订单或蓝字入库单选择形成上游范围；税率由采购订单直接带出，数量、金额及含税/不含税单价只读并由收票结算行派生，不形成第二套计价事实。暂估单价由采购订单行带出，在订单行只读展示，不随收票结算行变化，仅用于提交时的采购价差比较。

采购订单明细表展示字段顺序为：复选框、序号、采购类别、采购名称、规格、单位、验票数量、暂估单价、含税单价、价税合计、税率、不含税单价、税额、不含税金额、采购订单、订单行、采购入库单（蓝字）、入库行、服务结算单（蓝字）、结算行。收票结算行明细表字段顺序与订单行相同但不展示暂估单价，其中两项来源字段名称为“采购入库单”“服务结算单”，不显示“（蓝字）”。

上游来源候选按剩余可验票数量过滤：

- “选择采购订单”按供应商+项目过滤，勾选“是否存在合同”时再叠加合同；仅展示 `已验票数量 < 已入库/结算数量` 的采购订单行，并支持按业务类型查询实物采购或服务采购。
- “选择蓝字入库/服务结算”使用同一可选合同过滤口径；仅展示存在剩余可红冲验票数量的原蓝字采购入库行或原蓝字服务结算行。

### 5.1 蓝字采购收票

- 汇总主键：`采购订单号 + 订单行`。
- 展示采购订单、订单行、本次验票数量、不含税金额、税额、价税合计等订单维度结果。
- 同时展示采购入库单（蓝字）/入库行和服务结算单（蓝字）/结算行；实物采购仅填充入库来源，服务采购仅填充结算来源。
- 多个入库批次属于同一采购订单行时自动合并。
- 先发生红字入库、后收到净额蓝票时仍使用本汇总口径。
- 验票数量、价税合计、税额、不含税金额分别等于对应所有收票结算行同名字段之和。
- 税率取采购订单行；含税单价、不含税单价取对应收票结算行。多行对应同一订单行时，结算行的单价和税率必须一致，否则阻止提交。
- 未选择收票结算行前，税率根据采购订单立即显示；验票数量、含税单价、价税合计、不含税单价、税额、不含税金额显示为空。

### 5.2 红字采购收票

- 汇总主键：实物采购按`原蓝字采购入库单 + 入库行`；服务采购按`原蓝字服务结算单 + 结算行`。
- 同时展示采购订单和订单行；一条上游行的采购入库来源与服务结算来源互斥。
- 多条红字入库或红字服务结算来源冲减同一原蓝字来源行时自动合并。
- 验票数量、价税合计、税额、不含税金额按上述来源主键累加；含税单价、不含税单价、税率必须与同一原蓝字来源行对应的收票结算行一致，不一致时阻止提交并提示。

### 5.3 汇总口径判定

| 本次发票类型 | 业务情况 | 自动汇总主键 | 是否展示入库批次 |
| --- | --- | --- | --- |
| 蓝字 | 普通蓝字收票 | 采购订单号 + 订单行 | 否 |
| 蓝字 | 先红字退货、后开净额蓝票 | 采购订单号 + 订单行 | 否 |
| 红字 | 已收蓝票后退货并收到红票 | 原蓝字采购入库单 + 原蓝字入库行 | 是，同时展示采购订单和订单行 |

判断依据只取本次发票类型：本次收到蓝票即按订单行汇总；本次收到红票即按原蓝字入库行汇总。

## 6. 收票结算行

### 6.1 列表字段

字段及顺序必须严格为：

| 顺序 | 字段 | 规则 |
| ---: | --- | --- |
| 1 | 采购类别 | 选择采购入库行后带出 |
| 2 | 采购名称 | 选择采购入库行后带出 |
| 3 | 规格 | 选择采购入库行后带出 |
| 4 | 单位 | 选择采购入库行后带出 |
| 5 | 验票数量 | 可编辑；红票强制为负数，蓝票的红字入库行按负数冲减，其余蓝字入库行必须为正数 |
| 6 | 含税单价 | 选择采购入库行后带出 |
| 7 | 价税合计 | 自动计算 |
| 8 | 税率 | 选择采购入库行后带出 |
| 9 | 不含税单价 | 自动计算 |
| 10 | 税额 | 自动计算 |
| 11 | 不含税金额 | 自动计算 |
| 12 | 采购订单 | 选择后带出 |
| 13 | 订单行 | 选择后带出 |
| 14 | 采购入库单 | 实物采购行带出，服务采购行为空 |
| 15 | 入库行 | 实物采购行带出，服务采购行为空 |
| 16 | 服务结算单 | 服务采购行带出，实物采购行为空 |
| 17 | 结算行 | 服务采购行带出，实物采购行为空 |

### 6.2 参照采购入库单选择弹窗

- 入口：来源收票行上方“选择采购入库/服务结算”。
- 选择粒度：采购入库行或服务结算行。
- 选择范围：蓝字发票可选择已选采购订单行下游的蓝字、红字入库行；红字发票只能选择已选原蓝字入库行下游的红字入库行。
- 可验票条件：仅展示与已选上游行对应且 `|已验票数量| < |入库数量|` 的采购入库行；任一条件不满足均不展示。
- 数量方向：蓝字发票候选中的蓝字入库行，其入库数量、已验票数量均为正数；红字入库行两项均为负数。红字发票候选仅保留红字入库行，两项数量均为负数。
- 删除上游来源行后，同步移除不再匹配任何已选上游来源的收票结算行，并刷新验票总金额。
- 在上述范围内按供应商+项目过滤；仅勾选“是否存在合同”时叠加合同过滤。
- 未选择上游行时弹窗显示暂无数据。
- 弹窗列表不分页，符合条件的数据一次性展示。
- 未勾选记录时确认按钮禁用。
- 确认后将所选入库行追加到来源收票行，不覆盖已有行。

“选择采购入库/服务结算”弹窗列表字段及顺序必须严格为：入库/结算日期、类型、采购类别、采购名称、已入库/结算数量、已验票数量、采购订单、订单行、采购入库单、入库行、服务结算单、结算行。

“选择蓝字入库/服务结算”弹窗列表字段及顺序必须严格为：入库/结算日期、类型、采购类别、采购名称、已退货/结算数量、已退货/结算验票数量、采购订单、订单行、采购入库单、入库行、服务结算单、结算行。

上述两个弹窗的“类型”均指单据类型，字段值只能显示“蓝字”或“红字”，不得显示“采购入库”“服务结算”等来源业务类型。

### 6.3 来源选择弹窗查询条件

三类来源选择弹窗不再使用合并“关键字”查询，查询字段和顺序固定如下：

| 弹窗 | 查询条件（按展示顺序） |
| --- | --- |
| 选择采购订单 | 订单日期范围、业务类型（下拉）、采购类别（下拉）、采购名称、采购订单 |
| 选择蓝字入库/服务结算 | 入库/结算日期范围、采购类别（下拉）、采购名称、采购订单、采购入库单、服务结算单 |
| 选择采购入库/服务结算 | 入库日期范围、采购类别（下拉）、采购名称、采购订单、采购入库单 |

三类来源弹窗必须提供可演示的关联数据。供应商或项目未选择时无候选数据；两项已选择时按供应商+项目过滤，勾选“是否存在合同”并选择合同后再叠加合同条件。订单号、订单行、入库单号、入库行及数量金额必须前后一致。

其中“选择采购入库”不使用全量样例作为最终选择范围，必须叠加已选上游行条件；未选上游行时显示空态。

“选择蓝字入库/服务结算”仅展示原蓝字采购入库行或原蓝字服务结算行；实物来源填充采购入库字段，服务来源填充服务结算字段，两者互斥。

## 7. 金额计算

收票结算行选择后自动带出验票数量、含税单价、价税合计、税额和不含税金额，五项均允许经办人调整。调整验票数量或含税单价时，系统正向重算其他金额；直接调整价税合计、税额或不含税金额时，不反向计算验票数量或含税单价：

```text
默认验票数量 = 入库数量 - 已验票数量
不含税单价 = 含税单价 ÷ (1 + 税率)
价税合计 = 验票数量 × 含税单价
不含税金额 = 价税合计 ÷ (1 + 税率)
税额 = 价税合计 - 不含税金额
```

验票数量计算使用带符号的入库数量和已验票数量，不再取绝对值后单独补充正负号。数量符号及计算结果规则如下：

| 发票类型 | 可选履约来源类型 | 入库/结算数量、已验票数量符号 | 默认验票数量 | 示例 |
| --- | --- | --- | --- | --- |
| 蓝字 | 蓝字入库 | 正数 | 正数 | `10 - 3 = 7` |
| 蓝字 | 红字入库 | 负数 | 负数 | `-4 - (-1) = -3` |
| 红字 | 红字入库 | 负数 | 负数 | `-4 - (-1) = -3` |

验票数量允许调整，但不得超过该入库行的剩余可验票数量，也不得改变默认方向：默认值为正数时可调整区间为 `[0, 默认值]`；默认值为负数时可调整区间为 `[默认值, 0]`。输入相反符号或超出区间时，系统恢复为边界内的正确值。

不含税单价、税额、不含税金额、价税合计均保留两位小数。修改验票数量、含税单价或税率后立即重新计算行金额和验票总金额。

订单行与收票结算行表尾均显示“合计”，合计字段固定为验票数量、价税合计、税额、不含税金额；结算行调整后两张表的合计立即刷新。

```text
验票总金额 = 订单行价税合计汇总
盘存金额 = 发票金额 - 验票总金额
|发票金额| >= |验票总金额|
```

## 8. 提交校验

1. 发票号码、收票日期、类型、发票日期、发票金额、供应商、项目必填；勾选“是否存在合同”后合同名称必填。
2. 是否盘存勾选时盘存原因必填；盘存金额始终由系统计算，不允许手工修改。
3. 类型为“红字”时发票金额必须小于 0；类型为“蓝字”时发票金额必须大于 0。
4. 发票金额绝对值不得小于验票总金额绝对值。
4. 至少存在一条来源收票行；自动来源汇总不得作为提交事实判断依据。
5. 来源收票行每行验票数量必须符合来源方向及剩余可验票数量控制。
6. 来源收票行的采购订单、订单行、采购入库及入库行必须由来源选择带出，不允许手工修改。
7. 先红字退货、后开净额蓝票时，净可收票数量必须扣除有效红字入库数量。
8. 发票金额与验票总金额一致，允许 0.01 元舍入差异。
9. 已选收票结算行必须能追溯到当前已选上游行；切换蓝字/红字时同时清空上游行和收票结算行。
10. 同一采购订单号和订单行对应多条收票结算行时，含税单价、不含税单价、税率必须一致。
11. 红票所有收票结算行验票数量必须小于 0；蓝票中的红字入库行验票数量必须小于 0，蓝字入库行验票数量必须大于 0。
12. 草稿可编辑；待审核、已审核只读。
13. 提交时若存在订单行暂估单价≠含税单价，弹出“采购价差明细”弹窗，字段顺序为：采购类别、采购名称、规格、单位、验票数量、暂估单价、含税单价、单位价差、成本价差；单位价差=含税单价-暂估单价，成本价差=单位价差×验票数量；存在价差的金额突出显示（超暂估标红、低于暂估标绿），弹窗提示差异行数与成本价差合计；“取消”关闭弹窗停留详情且不提交，“确认提交”关闭弹窗并继续原提交流程；全部订单行暂估单价与含税单价一致时不弹窗。

## 9. 数据关系

```text
采购收票头 1 ── N 来源收票行
来源收票行 N ── 1 采购入库行
采购入库行 N ── 1 采购订单行

来源收票行 ── 自动派生 ── 自动来源汇总
```

收票结算行保留具体入库批次及红字冲减关系；订单行只承担展示与统计，不形成第二套持久化事实。

## 10. 验收标准

1. 新增和草稿详情显示“保存草稿”，点击后不因未填写必填字段而阻止保存。
2. 新增采购收票时收票日期为浏览器本地当日。
3. 供应商、项目均必填；来源弹窗默认按供应商+项目过滤，勾选“是否存在合同”并选择合同后才叠加合同条件，未勾选时不按合同过滤。
4. 是否盘存为默认不勾选的复选框；盘存金额只读等于发票金额减验票总金额，勾选后盘存原因启用且必填。
5. 类型为“红字”时，发票金额输入正数后自动显示为对应负数；切换回“蓝字”后自动恢复为正数。
6. 基础信息下方依次显示上游来源行、收票结算行。
7. 蓝字上游来源行选择采购订单行，红字上游来源行选择原蓝字采购入库行或服务结算行；上游行只用于限定下游范围和汇总，不重复计价。
8. 蓝票按采购订单+订单行汇总；采购订单明细表展示“采购入库单（蓝字）”“服务结算单（蓝字）”，收票结算行展示“采购入库单”“服务结算单”。
9. 红票实物采购按原蓝字采购入库单+入库行汇总，服务采购按原蓝字服务结算单+结算行汇总；每条数据仅有一类履约来源，且必须带出采购订单和订单行。
10. 先红字退货、后开净额蓝票时仍按订单行汇总，净可收票数量正确扣除红字入库。
11. 采购入库/服务结算弹窗可正常打开；未选择上游行时无数据，选择上游行后仅显示与其关联、符合可选合同过滤及尚未验完条件的下游入库行或服务结算行。
12. “选择采购订单”“选择蓝字入库/服务结算”“选择采购入库/服务结算”三个来源选择弹窗不分页，符合条件的数据一次性展示；选择后追加到对应明细表。
13. 验票总金额只汇总订单行价税合计，且发票金额绝对值小于验票总金额绝对值时阻止提交。
14. 页面不再显示红冲原因、原蓝字发票及原蓝票选择弹窗。
15. 备注前显示选填“发票附件”，草稿状态支持上传，非草稿状态不可上传。
16. 收票结算行选择后五项数量金额自动带出；修改验票数量或含税单价重算其他金额，修改价税合计、税额或不含税金额不反算数量、单价。
17. 完成供应商、项目、合同级联及上游来源选择后，采购入库弹窗存在可演示下游数据，且订单行、蓝字入库行与下游入库行可追溯。
18. Schema、策略、生成页面和采购付款专项浏览器回归通过。
19. 蓝票选择采购入库时可同时看到所选订单下游的蓝字、红字入库行；红字入库行按负数量冲减。
20. 蓝字订单行按采购订单+订单行汇总，红字订单行按原蓝字入库单+入库行汇总；同一汇总行多条结算行的含税单价、不含税单价、税率不一致时阻止提交。
21. 订单行、收票结算行均显示合计行，并正确汇总验票数量、价税合计、税额、不含税金额。
22. “选择蓝字入库单”中非零已退货数量、已退货验票数量均为负数。
23. 蓝票“选择采购入库”同时展示蓝字、红字入库行，蓝字行入库数量、已验票数量为正，红字行为负；红票仅展示所选蓝字入库单下游的红字入库行，两项数量均为负。
24. 采购订单剔除已验票数量大于等于已入库数量的行；蓝字入库单剔除已退货验票数量绝对值大于等于已退货数量绝对值的行；采购入库剔除已验票数量绝对值大于等于入库数量绝对值的行，并严格属于已选上游行。
25. 选择采购入库后，默认验票数量按“入库数量－已验票数量”计算；蓝字入库行结果为正数，红字入库行结果为负数。正数可调整区间为 `[0, 默认值]`，负数可调整区间为 `[默认值, 0]`，输入相反符号或超出区间时恢复为边界内的正确值。
26. 订单行在“验票数量”与“含税单价”之间显示只读“暂估单价”列，选择采购订单行时自动带出；暂估单价≠含税单价时提交先弹出采购价差明细，字段顺序、价差计算、突出显示和取消/确认提交按第8节第13条执行；无价差记录保持直接提交。
