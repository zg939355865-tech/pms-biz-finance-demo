## 2. 需求理解与 AI 假设

### 2.1 用户明确要求

1. 在采购管理中，于“采购入库”菜单下方新增“服务结算”菜单功能。
2. 服务结算支持选择采购订单进行结算。
3. 服务结算同时支持蓝字、红字正反向业务。
4. 服务结算用于确认服务业务完成程度，并作为后续采购收票、付款等业务的履约依据。
5. 基础信息、蓝字采购订单弹窗、红字蓝字结算单弹窗、服务结算明细、主列表和查询条件按 2026-09-08 提供的字段名称及顺序优化。
6. 蓝字结算数量为正数，红字结算数量为负数，绝对值均不得超过对应可结算/可红冲数量；本次结算金额自动等于明细价税合计。
7. 服务结算明细在复选框后、采购名称前增加“序号”，按当前明细行从 1 开始连续展示。

### 2.2 AI 补充内容与假设

1. **AI 假设：**“选择采购订单”实际选择采购订单明细行；订单行用于限定供应商、项目、服务内容、合同（如有）、单价和税率，不能只选择订单表头。
2. **AI 假设：**蓝字仅选择已审核、未终止、采购类别为服务且仍有可结算余额的采购订单行；同一服务订单行可分次结算。
3. **AI 假设：**红字仅选择原已审核蓝字服务结算行，并按原蓝字结算行的剩余可冲销数量、金额冲销；不得直接从采购订单重新创建无来源红字行。
4. 供应商由基础信息中的供应商选择器确定；采购订单行和蓝字结算行按所属公司、供应商过滤，切换供应商时清空已有明细，避免跨供应商混选。
5. 服务结算行的含税单价继承来源采购订单行且只读；用户维护结算数量，系统实时计算价税合计并汇总本次结算金额。
6. **AI 假设：**审核是服务履约确认动作，不设置多级审批、流程动态、当前责任人或流程图；审核后形成有效服务结算事实，反审核回草稿并撤销其有效性。
7. **AI 假设：**服务结算编号格式暂按 `SS+YYYYMMDD+3位序号` 生成。

## 3. 业务目标与范围

### 3.1 业务目标

按采购订单明细行确认服务实际完成数量及金额，保留蓝字确认和红字冲销的完整审计链路，为采购收票、应付确认和付款执行提供可追溯的履约事实。

### 3.2 主要使用人员

- 采购或项目经办人员：选择服务采购订单行，登记本次服务结算数量、服务期间及结算说明。
- 服务验收/结算审核人员：审核待审核结算单，确认其成为有效履约事实；必要时反审核。
- 财务及付款经办人员：查询已审核服务结算，作为采购收票和付款核销的业务来源。

### 3.3 本次包含

- 服务结算列表查询、固定分页、新增、草稿编辑、查看、删除及批量删除。
- 蓝字服务结算：从采购订单行多选并分次确认服务完成数量和金额。
- 红字服务结算：选择原已审核蓝字服务结算行，按原来源进行部分或全额冲销。
- 服务结算日期、服务期间、结算明细、附件及备注维护。
- 草稿提交、列表审核、列表反审核；审核人与审核时间留痕。
- 已审核服务结算行向采购收票提供可收票履约范围，并保留至采购订单行的穿透关系。

### 3.4 本次不包含

- 采购入库、物资数量、库存地点、库位、库存成本和物资退货。
- 服务验收标准、验收报告模板、工时填报、里程碑计划或独立验收流程。
- 发票登记、发票行—服务结算行分摊、付款申请、实际付款、付款核销和会计凭证生成。
- 服务结算价格变更、合同结算条款、预算强制拦截、税务口径及会计科目配置。
- 无采购订单服务结算、跨公司结算和跨供应商/跨项目合并结算。

### 3.5 业务链路

```text
已审核服务采购订单行
  -> 蓝字服务结算（确认实际完成） / 红字服务结算（冲销原蓝字完成）
  -> 审核后形成有效服务结算行
  -> 采购收票按服务结算行匹配
  -> 付款申请 / 付款核销
```

## 4. 页面组成与关系

| 视图 | 载体 | 说明 |
| --- | --- | --- |
| 服务结算列表 | 同一 HTML | 查询、分页、新增、批量删除、审核、反审核及进入详情 |
| 新增 | 同一 HTML 的详情视图 | 新建蓝字或红字结算单，维护基础信息和结算明细 |
| 编辑服务结算 | 同一 HTML 的详情视图 | 仅草稿可修改 |
| 查看服务结算 | 同一 HTML 的详情视图 | 待审核、已审核全字段只读 |
| 选择采购订单 | 多选弹窗 | 蓝字选择符合范围的服务采购订单行 |
| 选择蓝字服务结算行 | 多选弹窗 | 红字选择可冲销的原已审核蓝字服务结算行 |
| 审核确认 / 反审核确认 | 确认弹窗 | 单选列表记录后执行状态变更 |

页面关系：

- 点击“服务结算”菜单进入列表；菜单仅在正式页面交付时加入“采购入库”下方，本次蓝图不修改菜单源文件。
- 点击服务结算单号：草稿进入编辑，待审核和已审核进入只读查看。
- 蓝字选择采购订单行后，明细保留“服务结算行 → 采购订单行”关系；红字选择蓝字服务结算行后，明细同时保留“红字行 → 原蓝字服务结算行 → 采购订单行”关系。
- 已审核服务结算是后续采购收票的服务履约来源；采购收票、付款仍各自独立记录，不把三类事实平铺成同一明细表。
- 返回列表保留查询条件、页码和滚动上下文，不新增重复菜单标签。

## 5. 页面区域

### 5.1 列表视图

1. 页面标题：服务结算；右侧显示批量删除、审核、反审核和新增。审核、反审核仅选中一条符合状态的记录时启用。
2. 查询区域：服务结算单号、状态、类型、供应商、结算日期；每行最多四项，自然换行，不显示“更多筛选”。
3. 服务结算列表：展示服务结算单号、状态、类型、结算日期、供应商、创建人、创建时间和操作。
4. 分页区域：显示总记录数、固定“5条/页”和页码；不提供其他页容量选择，不产生业务区纵向滚动条。

### 5.2 详情视图

1. 详情页头：返回列表；草稿显示保存草稿、提交。审核、反审核仅在列表标题右侧执行，详情页不重复放置。
2. 基础信息页签：基础信息表单下方显示“服务结算明细”标题和可编辑明细表。
3. 结算明细：类型未选择或为蓝字时显示“选择采购订单”，红字时显示“选择蓝字结算单”；未选择类型或供应商时来源入口可见但禁用。切换类型或供应商清空已有明细。
4. 明细底部：实时合计结算数量、价税合计；红字合计按负数展示，基础信息“本次结算金额”同步等于价税合计。
5. 附件页签：维护服务确认单、验收单、服务报告等资料；页签内不重复显示“附件”标题。

## 6. 字段定义

仅明细字段：序号（`sequence`）、采购名称（`serviceName`）、规格（`serviceSpecification`）、单位（`unit`）、可结算/红冲数量（`availableQuantity`）、结算数量（`settlementQuantity`）、含税单价（`taxIncludedUnitPrice`）、价税合计（`taxIncludedAmount`）、行备注（`lineRemark`）、采购订单（`purchaseOrderNo`）、订单行（`purchaseOrderLineNo`）、蓝字结算单（`originalSettlementNo`）、结算单行（`originalSettlementLineNo`）。其中序号为表格展示字段，其余业务字段编码必须写入正式 Schema 的 `detailOnlyFields`。

## 7. 操作定义

### 7.1 列表操作

| 操作 | 位置 | 可用条件 | 执行结果 | 是否确认 |
| --- | --- | --- | --- | --- |
| 查询 | 查询区 | 始终可用 | 按条件筛选并回到第 1 页 | 否 |
| 重置 | 查询区 | 始终可用 | 清空条件并恢复默认列表 | 否 |
| 新增 | 页面标题右侧 | 有新增权限 | 进入空白新增视图，状态为草稿 | 否 |
| 批量删除 | 页面标题右侧 | 仅选中草稿记录 | 删除选中草稿并更新记录数 | 是 |
| 审核 | 页面标题右侧 | 单选待审核记录 | 状态变为已审核，写入审核人和审核时间，结算行成为有效履约事实 | 是 |
| 反审核 | 页面标题右侧 | 单选已审核记录且未被下游收票/付款引用 | 状态回到草稿，清空审核信息，撤销其有效履约事实 | 是 |
| 点击服务结算单号 | 列表首列 | 有查看权限 | 草稿进入编辑，其他状态进入全字段只读详情 | 否 |
| 删除 | 行操作 | 当前记录为草稿 | 删除当前服务结算单，不影响已审核履约统计 | 是 |

### 7.2 详情操作

| 操作 | 位置 | 可用条件 | 执行结果 | 是否确认 |
| --- | --- | --- | --- | --- |
| 返回列表 | 详情页头 | 始终可用 | 返回并保留列表上下文 | 有未保存修改时确认 |
| 保存草稿 | 详情页头 | 新增或草稿 | 保存当前内容，状态保持草稿并返回列表 | 否 |
| 提交 | 详情页头 | 草稿且校验通过 | 状态变为待审核，字段和维护操作锁定并返回列表 | 是 |
| 选择采购订单 | 基础信息页签的服务结算明细区 | 草稿、类型为蓝字 | 打开服务采购订单行多选弹窗 | 否 |
| 选择蓝字结算单 | 基础信息页签的服务结算明细区 | 草稿、类型为红字且已选择供应商 | 打开可红冲蓝字服务结算行多选弹窗 | 否 |
| 确认选择 | 来源选择弹窗 | 至少勾选一条符合条件行 | 去重带入明细并计算默认数量、金额和税额 | 否 |
| 删除结算行 | 明细行或工具栏 | 草稿且已选择行 | 从当前草稿删除，不影响来源订单或原蓝字结算 | 是 |
| 上传附件 | 附件页签 | 草稿 | 添加附件到附件列表 | 否 |
| 查看采购订单 | 明细采购订单号 | 有查看权限 | 通过父窗口打开对应采购订单详情标签 | 否 |
| 查看原蓝字服务结算单 | 红字明细原蓝字单号 | 有查看权限 | 通过父窗口打开对应原蓝字服务结算详情标签 | 否 |

## 8. 状态与权限

| 状态 | 页面只读性 | 可执行操作 | 可编辑内容 | 下一状态 |
| --- | --- | --- | --- | --- |
| 草稿 | 可编辑 | 返回列表、保存草稿、提交、删除、选择来源行、删除结算行、维护附件 | 除系统生成字段和来源快照外的可维护字段 | 待审核 |
| 待审核 | 全字段只读 | 返回列表、查看来源单据；列表可审核 | 无 | 已审核 |
| 已审核 | 全字段只读 | 返回列表、查看来源单据；列表可反审核 | 无 | 草稿 |

权限说明：

- 审核和反审核不设置审批意见、多级审批、审核记录页签、流程动态、当前责任人或流程图入口。
- 审核后，服务结算行才计入“累计有效结算数量/金额”和下游可收票范围；草稿、待审核、反审核回草稿的记录均不计入。
- 反审核前若该结算行已被采购收票、付款申请或付款核销有效引用，系统阻止反审核并列出引用单据；下游红字处理或解除引用后才可继续。此为 AI 假设，需业务确认。

## 9. 业务规则与校验

| 编号 | 触发时机 | 条件 | 处理结果 | 提示文案 |
| --- | --- | --- | --- |
| R01 | 新增 | 未选择类型 | 来源入口默认显示“选择采购订单”但禁用 | 请选择结算类型 |
| R02 | 蓝字选择来源 | 订单行非服务类别、非已审核、已终止或可结算数量小于等于 0 | 不展示或禁止选择 | 无可结算的服务采购订单行 |
| R03 | 红字选择来源 | 原蓝字结算行未审核或可冲销数量小于等于 0 | 不展示或禁止选择 | 无可冲销的蓝字服务结算行 |
| R04 | 选择来源 | 来源行所属公司或供应商与基础信息不一致 | 不展示或禁止选择 | 仅可选择当前公司、当前供应商的来源明细 |
| R05 | 切换类型或供应商 | 当前草稿已有结算明细 | 清空明细及来源快照，防止来源口径不一致 | 类型或供应商已变更，请重新选择结算来源 |
| R06 | 录入蓝字数量 | 本次结算数量小于等于 0 或大于最新可结算数量 | 阻止保存/提交；恢复到合法边界 | 本次结算数量必须大于 0 且不得超过可结算数量 |
| R07 | 录入红字数量 | 本次结算数量大于等于 0，或绝对值超过原蓝字行可冲销数量 | 阻止保存/提交；恢复到合法边界 | 红字结算数量必须为负数，且不得超过原蓝字可冲销数量 |
| R08 | 明细计算 | 修改结算数量 | 以来源含税单价重算价税合计；红字统一保留负号；本次结算金额同步等于价税合计汇总 | 不适用 |
| R09 | 提交 | 基础必填未完成、无明细、明细金额异常或来源余额已被其他已审核单据占用 | 阻止提交；按提交时最新余额重新校验 | 请补齐必填信息、至少保留一条有效结算明细并刷新可结算余额 |
| R11 | 审核 | 待审核单据通过审核 | 写入审核人、审核时间；状态变为已审核；计入有效履约数量和金额 | 审核成功 |
| R12 | 反审核 | 已审核单据未被下游有效引用 | 状态回草稿，清空审核人和审核时间；从有效履约统计中剔除 | 反审核成功 |
| R13 | 反审核 | 已审核单据被采购收票、付款申请或付款核销有效引用 | 阻止反审核 | 当前服务结算已被下游单据引用，不能反审核 |
| R14 | 删除 | 草稿删除或批量删除 | 二次确认后删除；已审核、待审核删除按钮禁用 | 确认删除所选草稿服务结算单吗？ |
| R15 | 业财一致性 | 已审核服务结算行作为收票来源 | 可收票数量/金额仅按有效蓝字结算减有效红字结算计算；不以采购订单审核金额直接替代履约金额 | 不适用 |

## 10. 关键交互

1. 查询、重置后回到第 1 页；查询条件按固定四列基线排列，日期使用起止日期范围。
2. 列表固定每页 5 条；服务结算单号固定左侧，操作列固定右侧；宽表仅在表格主体横向滚动。
3. 新增进入空白草稿，未选择类型不预填来源数据；草稿可保存、提交，其他状态只读；返回存在未保存修改时二次确认。
4. 蓝字和红字来源选择均为不分页的多选弹窗；选择后按来源唯一键去重，明细底部实时更新结算数量和价税合计。
5. 先通过供应商选择弹窗确定整单供应商，再选择对应供应商的采购订单行或蓝字结算行；切换供应商时清空已有明细。
6. 草稿状态附件可上传和删除；待审核、已审核状态附件只读。加载时显示标准加载态，无数据时显示空状态，选择弹窗无符合记录时显示空结果。
7. 通过 iframe 打开时，查看采购订单或原蓝字服务结算单使用 `postMessage` 通知父页面打开或切换对应标签；不生成重复标签。

## 11. 业财关联

### 11.1 归集维度

- 公司/核算主体、项目、供应商、采购订单、采购订单行、服务结算单、服务结算行。

### 11.2 上下游关系

- 上游来源：已审核服务采购订单行；红字另关联原已审核蓝字服务结算行。
- 当前单据：服务结算单头 1 ── N 服务结算行。
- 下游单据：采购收票的发票业务分摊、付款申请和付款核销。
- 穿透链路：`采购订单行 -> 蓝字/红字服务结算行 -> 发票业务分摊 -> 真实采购发票明细 -> 付款单/付款核销`。

### 11.3 财务影响

已审核服务结算确认服务履约数量和金额，是后续收票、应付及付款控制的业务基础；采购订单审核本身不等同于已履约。服务结算不直接生成发票、付款或凭证。本期是否在审核时生成暂估应付、具体会计科目和凭证规则未确认，正式 Schema 不得擅自固化。

## 13. 样例数据
