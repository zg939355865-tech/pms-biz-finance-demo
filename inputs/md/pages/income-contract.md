## 一、需要确认的业务假设

以下规则由 AI 根据当前需求和项目业财规范补充，生成 HTML 前请重点确认：

1. 一个收入合同支持绑定多个已立项项目；每条项目关系保留项目所属公司，后续按“公司 + 项目”归集成本。
2. 合同分类采用三个独立维度：合同性质为“试用合同、正式合同”；正式合同类型为“单次合同、框架合同”；合同层级为“主合同、子合同”。
3. 正式合同至少维护一条收款计划，收款计划金额合计必须等于合同含税金额后才允许提交审核。
4. 试用合同不维护收款计划，不产生收入，不进入开票、应收和收款流程。
5. 子合同必须关联一个主合同；主合同详情可只读查看其子合同清单，详情内不提供新增子合同入口，所有合同统一从列表页新增。
6. 付款方式为“一次性、阶段付款”。
7. 主合同允许不维护服务明细；子合同提交前必须至少维护一条服务明细。
8. 审核流程暂定为“草稿 -> 待审核 -> 已生效”；驳回后回到草稿。具体审核角色和多级审批不在本页面原型中展开。
9. 只有草稿合同可以编辑、删除和提交；待审核合同只能审核；已生效合同只读。

## 二、业务目标

统一管理与客户签订的试用合同和正式收入合同。合同支持关联多个已立项项目，并以每个项目的“所属公司 + 项目”作为后续收入、开票、回款和成本归集维度。

收入侧业务链路：

`已立项项目 -> 收入合同 -> 收款计划 -> 开票申请 -> 收款核销 -> 财务凭证`

### 5.6 收款计划

收款计划使用可编辑明细表。正式合同提交审核前至少存在一条计划；试用合同不显示收款计划编辑表，改为显示“不产生收入，无需维护收款计划”的提示。

工具栏：新增计划、删除选中计划、按比例拆分。

| 字段 | 规则 |
|---|---|
| 序号 | 系统生成 |
| 计划名称 | 必填，例如首付款、验收款、尾款 |
| 触发方式 | 必填，固定日期/项目里程碑/验收完成 |
| 关联里程碑 | 触发方式为项目里程碑时必填 |
| 计划收款日期 | 固定日期时必填；其他方式可根据触发节点自动计算 |
| 收款比例 | 必填，0% 至 100%，保留 2 位小数 |
| 计划收款金额 | 必填，保留 2 位小数，可由比例自动计算 |
| 是否需要开票 | 必填，是/否 |
| 开票时点 | 需要开票时必填，收款前/收款后/节点完成后 |
| 收款状态 | 系统维护，只读，未到期/待收款/部分收款/已收款/已逾期 |
| 已收款金额 | 系统汇总，只读 |
| 备注 | 选填 |

实时汇总区显示：合同含税金额、计划金额合计、计划比例合计、差额、已收款金额和未收款金额。

提交校验：

- 正式合同计划比例合计必须为 100%。
- 计划金额合计必须等于合同含税金额。
- 计划日期不得早于合同生效日期。
- 框架合同的计划金额合计不得超过框架总额；子合同金额合计不得超过框架总额。
- 校验失败时禁止提交，并在汇总区和对应单元格显示明确错误。

### 5.7 子合同

主合同详情只读展示子合同编号、名称、关联项目、合同金额和状态。该页签不提供新增子合同按钮；子合同统一从收入合同列表页新增并选择主合同。

### 5.8 审核与流程

审核记录、当前责任人和流程图统一通过详情页右上角流程入口查看，不设置独立页签。

## 六、状态与权限

| 状态 | 可编辑范围 | 可执行操作 |
|---|---|---|
| 草稿 | 合同信息、服务明细、关联项目；正式合同可编辑收款计划；子合同必须维护服务明细 | 保存、提交、删除 |
| 待审核 | 全部只读 | 审核通过、驳回 |
| 已生效 | 全部只读 | 查看、业务穿透 |

状态流转：

`草稿 -> 待审核 -> 已生效`

- 待审核驳回后回到草稿，并记录驳回意见。
- 审核通过后合同生效，锁定合同金额、关联项目和收款计划。
- 已生效合同的变更和终止不在本次原型范围内。

## 七、关键交互

1. 新增合同统一从列表页进入；子合同必须选择主合同，详情内不提供新增子合同入口。
2. 项目选择支持多选，首个项目带入客户和销售负责人；后续项目必须属于同一客户。
3. 合同性质选择“正式合同”后显示合同类型和收款计划；切换为试用合同时隐藏收款计划并将收入金额归零。
4. 修改合同金额后实时重算不含税金额、税额和收款计划差额，不自动覆盖用户已填写的计划金额。
5. 点击“按比例拆分”时根据现有比例计算计划金额，尾差计入最后一期。
6. 提交审核前统一校验必填项、关联项目、项目归集比例；子合同额外校验至少一条服务明细；正式合同同时校验合同金额和收款计划平衡关系。
7. 删除、驳回和更换项目必须二次确认。
8. 保存、提交、审核期间按钮进入加载状态，禁止重复点击。
9. 审核通过后刷新列表状态和金额汇总。
