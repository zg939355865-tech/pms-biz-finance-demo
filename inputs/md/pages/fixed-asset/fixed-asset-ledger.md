## 2. 需求理解与 AI 假设

### 2.1 用户明确要求

1. 固资台账支持从即时汇总库存中选择采购类别为“固定资产”的库存进行转固；转固成功后扣减对应即时库存。
2. 支持批量选择库存进行转固，但必须按单个固定资产生成台账。
3. 转固字段参照截图及 2026-09-08 增量要求，包含固定资产SN、名称、类别、使用部门、使用人员、项目、购置日期、折旧方法、原值、使用期限、残值率；必须包含转固日期、创建人、创建时间。
4. 固定资产在退还后不恢复为存货；资产卡片保持原卡片。
5. “转固信息”页签更名为“基础信息”，新增转固基础信息去除备注字段。
6. 即时库存弹窗查询条件去除库位，弹窗列表将库存余量移动到库存地点前。
7. 选择即时库存后，按库存余量以单位数量 1 自动拆分为逐件转固明细。
8. 转固明细、台账列表、查询条件和只读详情字段严格按 2026-09-08 用户指定顺序展示；点击固定资产SN进入只读详情。
9. 新增基础信息中创建人、创建时间各保留一处，去除公共策略补入的重复字段。
10. 转固明细“使用人员”改为下拉选择，并在使用人员与购置日期之间增加“项目”，默认“通用项目”。
11. 折旧方法限定为年限平均法、工作量法、双倍余额递减法、年数总和法、不计提折旧。
12. 只读详情在使用人员与购置日期之间增加“项目”。
13. 资产状态支持在用、闲置、报废、出售、其它；转固成功自动设为“在用”，其他状态由后续资产变更业务维护。
14. 只读详情在创建时间后增加“所属公司”，并将“当月折旧成本”更名为“月折旧成本”。

### 2.2 AI 补充内容与假设

1. **AI 假设：**固定资产编码由系统按资产卡片逐张生成并只读展示；固定资产SN在逐件明细中维护且同次转固不可重复，正式编码和SN唯一性范围待确认。
2. 一次转固可在即时库存选择弹窗中勾选多条库存记录；每条记录按即时库存数量自动拆分，库存余量为 N 时直接生成 N 条单位数量为 1 的转固明细，不能合并为一张卡片。
3. **AI 假设：**本期转固为无审批的非流程业务，详情仅提供“提交”，提交成功即生成资产卡片并扣减库存，不保留草稿。
4. 固定资产类别档案和各类别默认使用期限在本次需求中未给出取值口径；折旧方法按已确认的五种方式展示，残值率默认 0，不虚构类别枚举、默认年限或财务凭证规则。

## 3. 业务目标与范围

### 3.1 业务目标

将采购类别为“固定资产”的即时库存逐件转化为可追溯、可折旧的固定资产卡片，确保同一实物成本不会同时作为库存和固定资产重复存在。

### 3.2 主要使用人员

- 资产管理人员：选择可转固库存、维护资产折旧参数并生成资产卡片。
- 财务人员：查询资产原值、购置期间、折旧参数和转固日期。
- 仓储人员：核对转固扣减后的即时库存数量。

### 3.3 本次包含

- 固资台账查询、查看及从即时汇总库存批量选择后逐件转固。
- 固定资产SN、编码、名称、类别、使用部门、使用人员、项目、购置日期、折旧方法、原值、使用期限、残值率、转固日期、折旧成本、状态及创建审计字段维护或展示。
- 转固时扣减来源即时库存，生成与来源库存可追溯的资产卡片。

### 3.4 本次不包含

- 固定资产采购入库、资产领用、资产报废、处置、盘点、折旧计算、凭证生成及用友接口同步。
- 已生成资产卡片的批量合并、拆分、删除、原值或折旧参数追溯修改。
- 固定资产退还；该功能由“固资退还”菜单独立承载。

### 3.5 业务链路

```text
采购入库 -> 即时汇总库存（采购类别=固定资产） -> 批量选择可转固库存 -> 按件生成固资台账/资产卡片 -> 扣减即时库存 -> 后续固资退还或重新领用
```

## 4. 页面组成与关系

| 视图 | 载体 | 说明 |
| --- | --- | --- |
| 固资台账列表 | 同一 HTML | 查询、展示资产卡片和进入查看详情 |
| 转固详情 | 同一 HTML | 选择即时库存、维护转固参数、提交生成资产卡片 |
| 固资详情 | 同一 HTML | 只读展示已生成资产卡片及来源库存快照 |
| 选择即时汇总库存弹窗 | `ProDataSelectModal` | 仅选择采购类别为“固定资产”、库存余量大于 0 的即时库存记录，支持多选并按库存余量自动逐件展开 |

页面关系：列表点击“新增转固”进入空白转固详情；确认选择即时库存后按库存余量生成单位数量为 1 的逐件转固明细；提交后逐件生成资产卡片并返回列表。点击固定资产SN进入只读资产详情。固资退还后，本页仅更新原资产卡片的状态、归属和折旧成本归集部门，不新增库存或资产卡片。

## 5. 页面区域

### 5.1 列表视图

1. 面包屑和页面标题“固资台账”，标题右侧提供“新增转固”。
2. 查询区按四列栅格依次展示固定资产SN、固定资产名称、状态、固定资产类别、固定资产编码、转固日期；查询和重置在末尾右侧。
3. 台账列表依次展示固定资产SN、状态、转固日期、固定资产名称、固定资产类别、固定资产编码、使用部门、使用人员、购置日期、创建人、创建时间和操作列；固定资产SN固定左侧，操作列固定右侧。
4. 分页固定每页 5 条，不提供页容量选择；宽表仅表格区域可横向滚动。

### 5.2 详情视图

1. 详情页头提供“返回列表、提交”；查看模式只显示“返回列表”。
2. 页签名称为“基础信息”；新增转固使用三列 `DetailForm` 展示转固日期、创建人、创建时间和所属公司，不显示备注。
3. 转固明细使用 `EditableTable`，承载逐件转固的来源即时库存和每件资产参数；工具栏提供“选择即时库存”“删除选中明细”。
4. 新增转固时创建人、创建时间各显示一次，由系统带出并只读；查看模式切换为资产详情表单，按指定字段顺序全部只读且不显示转固明细。

## 8. 状态与权限

本页面无审批状态流转；资产状态为资产卡片业务状态，不代表转固审批状态。

| 权限 | 列表 | 详情 | 可执行操作 |
| --- | --- | --- | --- |
| 查看权限 | 查询、分页、查看卡片 | 只读 | 查询、重置、查看、翻页 |
| 转固维护权限 | 查询、分页、新增转固 | 可选择库存、维护明细、提交 | 查看权限全部操作、选择即时库存、删除明细、提交 |

资产状态说明：支持“在用、闲置、报废、出售、其它”。转固提交成功的资产卡片自动为“在用”；其余状态由后续资产状态变更业务维护，不允许在转固时直接选择。本页面不允许删除已生成资产卡片。

## 9. 业务规则与校验

| 编号 | 触发时机 | 条件 | 处理结果 | 提示文案 |
| --- | --- | --- | --- | --- |
| R01 | 打开即时库存弹窗 | 记录采购类别不是“固定资产” | 数据源层排除 | 不适用 |
| R02 | 打开即时库存弹窗 | 库存余量小于等于 0 或用户无库存地点权限 | 数据源层排除 | 不适用 |
| R03 | 确认选择库存 | 同一来源即时库存已在本次转固明细中 | 不重复新增 | 所选即时库存已存在于转固明细 |
| R04 | 提交 | 未选择任何转固明细 | 阻止提交 | 请至少选择一条即时库存 |
| R05 | 提交 | 转固日期或任一明细的固定资产SN、名称、类别、使用部门、使用人员、项目、购置日期、折旧方法、原值、使用期限、残值率为空 | 阻止提交并定位首个字段 | 请完善固定资产转固信息 |
| R06 | 确认选择库存 | 来源库存余量为 N | 自动生成 N 条单位数量为 1 的逐件明细 | 不适用 |
| R07 | 提交并发校验 | 来源库存最新余量小于本次已拆分明细数 | 阻止提交并刷新可转固数量 | 即时库存已变化，请重新确认转固数量 |
| R08 | 提交 | 原值小于等于 0、使用期限不是正整数或残值率不在 [0%,100%) | 阻止提交 | 请检查原值、使用期限和残值率 |
| R09 | 提交 | 同一来源库存拆分为多件转固 | 为每件生成唯一固定资产SN、固定资产编码和独立资产卡片 | 不适用 |
| R10 | 提交事务 | 任一资产卡片生成或库存扣减失败 | 整次转固不生成部分资产卡片、不扣减库存 | 转固失败，资产卡片和库存未更新 |
| R11 | 转固成功 | 每件资产卡片生成 | 来源即时库存按转固数量扣减，不生成入库或出库流水以外的重复库存事实 | 不适用 |
| R12 | 固资退还成功 | 原资产卡片被退还 | 仅更新原卡片状态、使用归属和折旧成本归集部门，不恢复即时库存 | 不适用 |
| R13 | 选择即时库存 | 生成逐件转固明细 | 项目默认带入“通用项目”，允许用户改选其他有权限项目 | 不适用 |
| R14 | 转固提交成功 | 每件资产卡片生成 | 状态自动设为“在用”；闲置、报废、出售、其它只能由后续变更产生 | 不适用 |

金额及业财一致性：每张资产卡片原值取对应单件转固原值；同一来源库存的本次全部资产卡片原值合计应可追溯至来源库存的转固成本。采购入库单价、库存计价、折旧额、会计科目和凭证生成规则未确认，不在本期虚构计算公式或财务结果。

## 10. 关键交互

1. 查询、重置后回到第 1 页；列表固定每页 5 条，不提供页容量选择，不展示通用 Toast。
2. 新增转固进入空白详情，创建人、创建时间、所属公司自动带出，创建人和创建时间各仅显示一次；无即时库存选择时转固明细显示空状态。
3. 即时汇总库存弹窗仅提供符合“采购类别=固定资产、库存余量>0”的记录，支持多选；查询条件不含库位，库存余量列位于库存地点前。
4. 确认选择后，库存余量为 N 的来源行立即展开为 N 条单位数量为 1 的转固明细；使用人员使用下拉选择，项目默认“通用项目”，列表中每张卡片独立成行并拥有唯一固定资产SN和固定资产编码。
5. 提交前重新读取来源即时库存余量；成功后刷新本页列表和即时汇总库存可用数量，失败时保留已填写转固信息以便修正。
6. 已生成资产卡片点击固定资产SN只读查看，详情字段全部不可编辑；后续退还造成的状态、归属和折旧成本归集部门变化在原卡片上展示，不新增卡片。
7. 宽明细仅在表格区域横向滚动；复选框、序号、采购名称固定左侧，操作固定右侧；页面整体无横向滚动；未提交离开时提示确认。
8. 页面支持直接打开和 iframe 嵌入；菜单切换与父级标签页通信遵循项目规范。

## 11. 业财关联

### 11.1 归集维度

- 所属公司、固定资产SN、固定资产编码、固定资产类别、使用部门、使用人员、项目、来源库存地点、库位、采购名称、购置日期、转固日期。

### 11.2 上下游关系

- 上游来源：采购类别为“固定资产”的即时汇总库存记录。
- 当前单据：固资台账/固定资产卡片及转固明细。
- 下游单据：固资退还；资产领用、折旧和用友同步待后续业务确认。
- 穿透链路：`采购入库 -> 即时汇总库存 -> 转固明细 -> 单张固定资产卡片 -> 固资退还`。

### 11.3 财务影响

转固在业务上减少存货实物结存并形成固定资产原值基础，必须防止同一实物同时留在库存和资产台账。固定资产折旧计算、会计凭证、固定资产模块接口及同步时点未确认，本页面不直接声明凭证生成或折旧入账。
