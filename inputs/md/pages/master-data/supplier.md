## 2. 需求结论

1. 页面固定包含基础信息、财务信息、银行信息、联系人四个页签。
2. 供应商编码由用户录入，供应商编码和名称在集团范围内唯一。
3. 页面不保留供应商启用、停用状态。
4. 统一社会信用代码非必填；财务供应商编码由财务系统回传并只读展示。
5. 基础信息不再维护准入公司；查询、列表、规则及样例数据同步移除准入公司。
6. 供应商类型后增加必填的供应商等级，选项为 `A、B、C`。
7. 结算币别改为可选下拉，默认 `CNY`；账期（天）改为下拉，选项为 `0、30、60、90、120`。
8. 银行信息与联系人为一对多行内明细，提交时至少各维护一条。

## 3. 页面组成

| 视图 | 说明 |
| --- | --- |
| 供应商列表 | 查询、固定五条分页、批量删除、新增及进入详情 |
| 基础信息 | 维护供应商身份、分类、等级、地址及审计信息 |
| 财务信息 | 维护财务编码、发票类型、结算币别、付款方式和账期 |
| 银行信息 | 行内维护供应商银行账户 |
| 联系人 | 行内维护供应商联系人 |

列表与详情共用同一 HTML。点击供应商编码进入详情，点击“返回列表”回到原列表上下文；四个页签统一提交。

## 4. 页面区域

### 4.1 列表视图

1. `PageHeader`：标题“供应商管理”，右侧显示“批量删除、 新增供应商”。
2. `ProSearchForm`：三项查询条件全部展示，不提供更多筛选。
3. `ProTable`：显示用户指定的七个业务字段；供应商编码固定在左侧，操作列固定在右侧。
4. 分页固定 `5条/页`，不提供页容量切换，不产生业务页面内层纵向滚动。

### 4.2 详情视图

1. 顶部右侧显示“返回列表、提交”。
2. `ProTabsDetail` 按基础信息、财务信息、银行信息、联系人顺序展示。
3. 基础信息与财务信息使用三列 `DetailForm`。
4. 银行信息与联系人使用 `EditableTable`，支持新增行、删除选中明细和行删除。

## 6. 操作与规则

| 编号 | 触发 | 规则 | 提示 |
| --- | --- | --- | --- |
| R01 | 提交 | 必填字段或明细必填单元格为空 | 请完善必填信息 |
| R02 | 提交 | 供应商编码在集团范围内重复 | 供应商编码在集团范围内不能重复 |
| R03 | 提交 | 供应商名称在集团范围内重复 | 供应商名称在集团范围内不能重复 |
| R04 | 提交 | 未维护银行账户或联系人 | 请至少维护一条银行账户和一名联系人 |
| R05 | 提交 | 同一供应商存在重复银行账号 | 银行账号不能重复 |
| R06 | 删除 | 供应商已被业务单据引用 | 当前供应商已被业务引用，不能删除 |

本页面无审批状态流转，不保留供应商启用、停用状态。历史合同、订单、入库、发票和付款单继续使用已固化快照，不因主档后续修改而被回写。

## 7. 演示数据与验收

1. 列表至少12条供应商数据，首屏固定显示5条。
2. A、B、C三个供应商等级均有可查询数据。
3. 至少一条统一社会信用代码为空，以验证该字段非必填。
4. 财务信息展示财务系统回传编码，结算币别默认CNY且可选择。
5. 银行明细仅显示开户银行、银行账号、账户名称、国家、账户币别。
6. 联系人仅显示联系人、职务、手机号码、固定电话、邮箱。
7. 1440px及2048px桌面宽度下不产生页面级横向滚动；明细表过宽时仅表格内部横向滚动。

## 8. 组件与资源约束

- 页面复用 `pms-resource-center-v1` 的 `PageHeader、ProSearchForm、ProTable、ProTabsDetail、DetailForm、EditableTable`。
- 不新增页面私有基础组件，不直接编辑生成后的 HTML。
- 正式链路：蓝图 → Schema → 页面生成 → Schema/Policy/Page检查 → 供应商专项浏览器回归。
