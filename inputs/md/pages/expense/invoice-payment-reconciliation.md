## 3. 页面与业务边界

- 一张核销单以一张付款单为整单维度，付款单可分多次、跨月核销。
- 付款单与发票保持多对多关系；每次核销保存付款单—发票—本次核销金额分配明细。
- 选择付款单后，系统按付款公司、供应商和可核销余额加载待核销发票，不要求付款申请人直接关联业务单据。
- 付款单选择范围仅包含已付款且未核销金额大于 0 的付款单；弹窗采用单选、1080px 宽度和固定 5 条/页。
- 待核销发票范围仅包含已审核、与付款单供应商一致且存在未核销余额的发票；蓝字余额为正，红字余额为负，未参与本次核销的发票本次金额可保持 0。
- 发票与业务单据的后台分摊关系继续保留，用于审计追溯，但本页面不再展示“发票与业务”页签。
- 本次核销金额小于付款未核销金额时，审核后付款单保持部分核销；剩余金额允许后续月份继续核销。

## 4. 页面结构

### 4.1 列表

- 查询条件：付款单号、状态、供应商、合同名称、项目、核销日期。
- 列表字段按“单据识别 → 日期与金额 → 主体信息 → 审计信息”分组：付款单号、状态、核销日期、付款金额、本次核销金额、供应商、合同名称、项目、创建人、创建时间。
- 付款单号固定在左侧，状态紧跟付款单号；付款金额和本次核销金额连续右对齐，创建人、创建时间位于业务字段末尾，操作列固定在最右侧。
- 状态：草稿、待审核、已审核。
- 草稿允许删除；付款单号为进入详情的唯一入口；固定每页 5 条。

### 4.2 详情

详情仅保留一个“基础信息”页签，页签内容顺序如下：

1. `DetailForm`：展示整单基础信息。
2. `EditableTable`：展示该付款单对应的待核销发票。

不再展示“付款信息”“发票与业务”“调整历史”页签，也不在内容区重复显示“基础信息”区块标题。
9个核销业务字段之后依次展示所属公司、创建人、创建时间、审核人、审核时间、备注。所属公司、创建人使用具体业务值；审核字段由审核动作自动维护；备注仅在草稿状态可编辑。

### 5.2 待核销发票

| 顺序 | 字段 | 控件 | 必填 | 编辑规则 | 数据来源 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 发票号码 | 文本 | 否 | 只读 | 已审核采购收票 |
| 2 | 类型 | 标签 | 否 | 只读 | 蓝字、红字 |
| 3 | 发票日期 | 日期 | 否 | 只读 | 发票 |
| 4 | 发票金额 | 金额 | 否 | 只读，红字为负数 | 发票价税合计 |

| 6 | 本次核销金额 | 金额输入 | 否 | 草稿可编辑；蓝字为正；红字输入正数后自动转为负数，未参与时填 0 | 本次付款分配金额 |

表格底部显示“合计”行，合计值位于“本次核销金额”列，并与基础信息“本次核销金额”保持一致。

## 6. 状态与操作

| 状态 | 详情模式 | 可用操作 |
| --- | --- | --- |
| 草稿 | 可编辑核销日期和发票本次核销金额 | 保存草稿、提交 |
| 待审核 | 只读 | 审核 |
| 已审核 | 只读 | 返回列表 |

提交后状态由草稿变为待审核；审核通过后变为已审核，自动记录审核人和审核时间，并正式占用付款、发票未核销余额。反审核恢复草稿时清空审核人和审核时间。

## 7. 业务规则

| 编号 | 规则 |
| --- | --- |
| R01 | 待核销发票必须与付款单供应商一致，并处于已审核且存在未核销余额的有效状态；蓝字余额大于0，红字余额小于0。 |
| R02 | 蓝字发票本次核销金额范围为0至未核销金额；红字发票范围为未核销金额至0，参与核销时必须为负数。 |
| R03 | 基础信息“本次核销金额”等于全部发票明细“本次核销金额”之和。 |
| R04 | 整单本次核销金额不得超过付款单未核销金额。 |
| R05 | 允许本次核销金额小于付款单未核销金额；审核后付款单进入部分核销状态，剩余金额允许跨月继续核销。 |
| R06 | 草稿和待审核记录仅占用可核销额度，不正式冲减余额；已审核后正式更新付款和发票未核销金额。 |
| R07 | 同一发票被其他核销单占用或审核后，提交和审核时重新校验可用余额，避免超额核销。 |
| R08 | 已审核记录不得直接修改；需要调整时通过反核销或红冲记录处理，后台保留完整审计轨迹。 |
| R09 | 付款单选择弹窗只返回已付款且未核销金额大于 0 的记录，确认后一次性回填基础信息和待核销发票。 |
| R10 | 提交时整单本次核销金额必须大于 0；单行填 0 表示本次不核销该发票。 |
| R11 | 红字发票的发票金额、未核销金额和本次核销金额统一按负数存储与展示。 |
| R12 | 红字发票本次核销金额无需手工输入负号，输入或粘贴正数后系统立即转换为对应负数，并重新计算整单合计。 |
