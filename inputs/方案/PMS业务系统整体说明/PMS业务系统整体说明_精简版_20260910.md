# PMS业务系统整体说明

## 一 总体定位与范围

PMS 是以项目为主线的业务管理平台，将项目进展、采购、物资、收入、收付款和资产记录关联起来，方便查询业务进度、追溯来源和月末核对。

**当前范围**：项目需求至计划执行及运维记录，采购订单与履约、收票付款，物资出入库，收入合同与结算、开票收款，库存转固与资产归属变更，以及物资、收入、采购的期末检查与结账。

**后续建设**：补齐项目验收结项、成本归集分析，完成用友财务对接、界面优化和业务 Agent。

**不替代的系统职责**：PMS 不承担总账、正式会计核算、法定财务报表、税务开票及银行支付，也不建设专业仓储作业、人力薪酬等系统。

当前交付为业务设计与静态原型，页面展示不等于正式上线；用友接口、自动凭证和 Agent 等能力需开发、联调及验收。

## 二 各模块业务流程

**项目管理**：项目需求 → 调研与方案 → 实施通知 → 立项与计划 → 进度填报及运维记录。集中记录项目阶段、任务和责任人；独立验收、结项尚未纳入当前可用范围。

**采购管理**：支出合同可选关联 → 采购订单 → 物资或资产采购入库，服务采购办理服务结算 → 按订单及已审核履约记录收票。付款单直接登记实际付款，再通过票款核销关联采购发票；采购申请、付款申请当前未开放。

**库存管理**：采购入库或其他入库增加库存，物资出库或其他出库减少库存，同步形成库存余额与出入库流水。物资出库记录项目去向；当前不含调拨、盘点和库存成本计价。

**收入管理**：建立收入合同及收款计划后，分别办理项目结算、按收款计划开票、登记实际收款，再将收款与销项发票核销。结算、开票和收款不强制串行，便于分别查看各环节的完成情况。

**固定资产**：固定资产类库存 → 逐件转为资产卡片并扣减库存 → 通过固资变更单调整使用人、部门或项目等归属。记录资产来源及变更，当前不执行折旧计算、盘点和报废处置。

**成本管理**：属于后续建设。拟将采购、领料、费用、人工和折旧等成本按项目或部门归集、分摊和复核，再形成成本分析；当前尚不能自动计算完整项目成本及毛利。

**结算管理**：结算分布在采购与收入流程中，并非独立模块。采购侧以入库或服务结算确认履约，收入侧按合同收款计划及项目办理项目结算；业务结算不等同于开票或收付款。

**期末关账**：检查当前期间的物资、收入、采购单据 → 列出未完成事项及责任人 → 处理后复查 → 全部通过后执行期末结算。原型包含用友同步步骤及结果展示，真实接口待联调；当前不含固资和成本检查。

## 三 这样设计的价值

1. **项目进展更清楚**：把阶段、计划、进度和责任人放在统一入口，减少依赖口头汇报和分散表格了解项目情况。

2. **业务依据更好查**：订单、入库或服务结算、发票与收付款通过来源和核销关系关联，便于核对货或服务是否完成、票款是否对应。

3. **物资和资产去向更清楚**：库存流水记录收发，资产卡片记录使用人及归属变更，便于查来源、查余额、查责任。

4. **少重复录入和来回核对**：下游单据引用上游信息，并按数量、金额、状态等规则校验，减少多份台账重复维护和人工核对。

5. **月末问题集中处理**：结账前列出未完成事项和责任人，检查未通过不能正常结账，减少逐人询问和遗漏。

以上是设计机制支持的价值，实际节省的时间和费用需上线后统计。减少打印、传单和重复归档可作为附加收益，不作为核心建设价值。

## 四 设计原则与建设安排

**设计原则**：以项目关联业务；合同、履约、票据和资金分别记录；保留单据来源与操作记录；在提交、审核和关账时检查规则；PMS 管业务，用友管正式财务核算。

**版本规划**：第一阶段完成项目全生命周期管理；第二阶段完成采购、库存、收入、固资、成本、结算和关账；第三阶段完成用友财务对接、UI 优化和业务 Agent 开发。

**推广安排**：以长沙为基线，验证流程和规则、统一基础数据，再逐步推广至武汉及其他公司。优先复用标准版本，配置必要差异，减少重复开发和管理口径不一致。
