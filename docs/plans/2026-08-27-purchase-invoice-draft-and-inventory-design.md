# 采购收票草稿与盘存联动设计

## 设计结论

- 采购收票继续使用列表审核、草稿详情编辑模式；新增和草稿详情提供“保存草稿、提交”。
- 保存草稿不执行提交必填校验，状态保持“草稿”；提交时统一校验基础信息、条件必填和明细规则。
- 新建时收票日期按浏览器本地日期默认当天，编辑时保留单据原值。
- 合同名称改为必填下拉框；项目保留标准项目选择弹窗并改为必填。
- 是否盘存默认“否”。为“否”时盘存金额、盘存原因禁用且无输入提示；为“是”时启用并动态显示必填标识。

## 实现与验证

- Schema 使用公共 `auditable-list-detail` 策略和 `requiredWhen`、`editableWhen` 条件规则，不增加页面私有样式或交互脚本。
- 页面由正式 Schema 重新生成。
- 专项回归覆盖草稿保存、当日默认值、合同下拉、项目必填及盘存条件状态切换。
