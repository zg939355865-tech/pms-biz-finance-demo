# 智能体运营分析页面规则治理方案

## 目标

将本次页面反复修正暴露出的公共规则问题，从页面级补丁改为可复用、可校验的生成能力，避免后续页面再次出现字段列数、页签重复标题、卡片排列和旧结构残留等偏差。

## 治理方案

1. Schema 显式声明列表页容量、详情表单列数、页签标题规则、卡片每行数量和卡片指标列数。
2. 页面生成器将上述声明输出为通用数据属性，不依赖具体页面 ID。
3. 公共样式仅依据组件类型和数据属性布局；桌面端按 Schema 列数展示，窄屏按统一断点降为两列或一列。
4. Schema 检查在生成前校验约束，发现字段列数、卡片布局或页签标题不符合时直接失败。
5. 浏览器验收同时覆盖独立页面和完整菜单 iframe 场景，检查实际计算后的布局，不只检查 HTML 字符串。
6. 生成源中删除已废弃的控制前后值和主列表行展开结构，保证旧需求不会被后续重新生成。

## 本页约束

- 主列表固定每页 5 条。
- 详情表单桌面端每行 3 个字段。
- 三个页签的直接内容区不重复显示页签同义标题。
- 控制策略和整体进展各独占一行并上下排列。
- 控制效果记录每行 1 张卡片，卡片内六项指标桌面端每行 3 项。
- 已部署智能体作为只读多值标签展示，不显示下拉操作提示。

## 验收门槛

生成源检查、Schema 检查、静态页面检查、浏览器交互检查和菜单环境检查全部通过后方可交付。
