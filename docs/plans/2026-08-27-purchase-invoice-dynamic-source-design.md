# 采购收票动态来源设计

> 状态说明：本文“最终确认：来源收票行与自动汇总”一节为当前有效方案，覆盖下方历史目标、方案及默认态描述；旧段仅保留方案演进记录。

## 目标

- 蓝字订单明细选择采购订单，红字订单明细选择蓝字入库单。
- 收票结算明细不受蓝红字影响，始终选择采购入库。
- 两张明细表和三类来源弹窗严格使用用户指定字段名称及顺序。

## 方案

1. 订单明细工具栏配置两个互斥按钮，按 `invoiceNature` 控制显隐并分别打开采购订单、蓝字入库单弹窗。
2. 类型切换时清空订单明细，避免采购订单行与蓝字入库行在同一来源表中混用；收票结算明细不清空。
3. 蓝字入库单弹窗沿用标准 `ProDataSelectModal`，按供应商过滤并保留采购入库、采购订单两层追溯字段。
4. 收票结算明细按钮固定为“选择采购入库”，弹窗补全采购入库单号和入库单明细行。
5. 宽表沿用公共横向滚动和工具栏对齐样式，金额、数量右对齐，来源编号左对齐。

## 验收

- 蓝字、红字按钮互斥且文案、目标弹窗正确。
- 切换类型后订单明细清空，收票结算按钮保持不变。
- 三类弹窗及两张明细表字段顺序与需求完全一致。
- 选择来源后可追加明细，金额汇总继续正确。

## 默认态与数量派生补充

1. 新增时类型为空，来源按钮按蓝字默认态显示“选择采购订单”，但不替代类型必填校验。
2. 订单明细验票数量改为只读、非必填，按“采购订单 + 订单明细行”汇总收票结算明细验票数量。
3. 收票结算明细是验票数量与金额事实层；订单明细是订单行汇总层。验票总金额仅汇总收票结算明细，避免重复计价。
4. 所属公司由采购收票页面显式声明，放在审核时间之后、备注之前，并使用具体业务主体；公共策略只负责缺失审计字段补齐，不覆盖本页真实值和位置。
5. 三个来源按钮不依赖前置字段启用；弹窗始终可打开。来源表统一按供应商编码、合同名称、项目编码三项过滤，任一条件为空时结果为零，三项完整时展示匹配数据。

## 最终确认：来源收票行与自动汇总

以下规则为 2026-08-27 最新确认方案，覆盖本文前述“订单明细独立选择采购订单或蓝字入库单”的设计。后续实现不得要求经办人重复选择订单明细。

```text
来源收票行：数量、金额和业务追溯事实
自动来源汇总：只读派生，不独立选择、不编辑、不重复保存
```

### 蓝字采购收票

- 按`采购订单号 + 订单行`自动汇总。
- 汇总表不展示蓝字采购入库单和入库行。
- 多个入库批次属于同一采购订单行时自动合并，具体批次继续保存在后台来源收票行。
- 货到票未到期间已经发生红字入库，后续收到净额蓝票时仍按订单行汇总；红字入库只参与净可收票数量计算。

### 红字采购收票

- 按`原蓝字采购入库单 + 原蓝字入库行`自动汇总。
- 汇总表同时展示原蓝字采购入库单、原蓝字入库行及其对应的采购订单、订单行。
- 多条红字入库来源冲减同一原蓝字入库行时自动合并。

### 判定规则

| 本次发票类型 | 业务情况 | 自动汇总主键 | 是否展示入库批次 |
| --- | --- | --- | --- |
| 蓝字 | 普通蓝字收票 | 采购订单号 + 订单行 | 否 |
| 蓝字 | 先红字退货、后开净额蓝票 | 采购订单号 + 订单行 | 否 |
| 红字 | 已收蓝票后退货并收到红票 | 原蓝字采购入库单 + 原蓝字入库行 | 是，同时展示采购订单和订单行 |

核心判断：本次收到蓝票即按订单行汇总；本次收到红票即按原蓝字入库行汇总。历史是否存在红字入库只影响净可收票数量，不改变蓝票汇总主键。验票总金额只汇总来源收票行，自动来源汇总不得再次参与合计。
